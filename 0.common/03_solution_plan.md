# 03. 솔루션 기획안 (초안)

> 해커톤 시작 전에는 기획만. 코드/데이터 산출물은 대회 시작 후 작성.

## 1. 컨셉

**"FireCalendar" (가칭)** — 지도에서 지역을 고르면, 2001년부터 오늘까지의 화재 활동을 **센서와 무관한 하나의 캘린더**로 보여주고, "지금이 평소보다 얼마나 심한가"를 한눈에 알려주는 웹 앱.

## 2. 사용자 시나리오

1. 아르헨티나 지방 소방 담당자가 앱 접속
2. 지도에서 관할 구역을 폴리곤으로 그림 (또는 위경도 bbox 입력)
3. 기간 선택 (기본: 전체 2001–현재)
4. 결과 화면:
   - **요약 카드**: "이번 달 핫스팟 1,240개 — 평년 중앙값 대비 +180%, 25년 중 3위"
   - **연소 캘린더 히트맵** (연도×월)
   - **월별 기후값 vs 올해** 라인 차트
   - **연도별 총합** 막대 차트
   - **지도**: 선택 기간 핫스팟 밀도
5. CSV(원시 핫스팟 / 월별 집계) 및 PNG/PDF 리포트 다운로드

## 3. 아키텍처

```
[FIRMS 아카이브 CSV (MODIS SP, VIIRS SP)] + [FIRMS API (최근 NRT)]
                │
                ▼
  ┌─────────────────────────────┐
  │ 데이터 파이프라인 (Python)    │  pandas / polars / DuckDB / geopandas
  │ 1. 품질 필터 & type 필터       │
  │ 2. 그리드 집계 (0.1°, 월)      │
  │ 3. 하모나이즈 모델 적합/적용   │
  │ 4. Parquet 저장               │
  └─────────────────────────────┘
                │
                ▼
  ┌─────────────────────────────┐
  │ 백엔드 API (FastAPI)          │  DuckDB로 Parquet 직접 쿼리
  │ /calendar?geom=&start=&end=  │  → 월별 harmonized count, 기후값, 이상치
  │ /hotspots.csv?geom=...       │  → 원시 핫스팟 (작은 AOI만)
  │ /nrt  (최근 7~10일 FIRMS API) │
  └─────────────────────────────┘
                │
                ▼
  ┌─────────────────────────────┐
  │ 프론트엔드                    │  React(or Vite+vanilla) + Leaflet/MapLibre
  │ - AOI 드로잉, 좌표 입력        │  + leaflet-draw / terra-draw
  │ - 캘린더 히트맵, 차트          │  ECharts / Plotly / D3
  │ - 다운로드                    │
  └─────────────────────────────┘
```

### 대안 (서버 최소화)
- 그리드 집계 결과를 국가/지역 단위 정적 Parquet/JSON으로 만들어 **DuckDB-WASM**으로 브라우저에서 직접 쿼리 → GitHub Pages 등 정적 호스팅 가능. 배포 리스크 감소.

## 4. 기능 우선순위

| 우선순위 | 기능 |
|---|---|
| **P0 (필수)** | 하모나이즈 데이터(데모 지역 2~3곳), AOI bbox 선택, 연소 캘린더 히트맵, 이상치 요약, CSV 다운로드 |
| **P1 (중요)** | 폴리곤 드로잉, 보정 전/후 비교 토글, 월별 기후값 차트, 연도별 차트, 색각이상 친화 팔레트 |
| **P2 (여유 시)** | 전 지구 커버리지, NRT 실시간 반영, PNG/PDF 리포트, 다국어(영/스페인어/한국어), FRP 기반 강도 지표 |

## 8. 리스크 & 대응

| 리스크 | 대응 |
|---|---|
| 20년치 데이터 용량/다운로드 지연 | 데모 지역만 먼저 확보, 국가별 CSV 활용, 그리드 집계본만 저장 |
| 하모나이즈 정확도 부족 | 단순 기법(A/D)을 먼저 완성 후 고도화; 불확실성 표시로 투명성 확보 |
| 화재 적은 지역에서 비율 불안정 | 층화(바이옴) 단위로 계수 추정, 셀 단위는 shrinkage |
| MODIS 운영 종료로 최신 MODIS 없음 | 최신 구간은 VIIRS만 사용하므로 오히려 VIIRS 기준 통일이 유리 |
| 시간 부족 | P0 범위 엄수, 목업 데이터로 프론트 병렬 개발 |
| 배포 실패 | 정적 호스팅 + DuckDB-WASM 대안 확보 |

## 9. 발표 스토리 뼈대

1. **문제**: 20년 화재 기록이 2012년에 "끊겨 있다" — 보정 전 그래프로 가짜 증가 추세 시연
2. **해결**: 중첩 기간을 이용한 하모나이즈 → 보정 후 매끄러운 시계열
3. **검증**: 교차검증 수치 + 실제 대형 화재 시즌 이상치 탐지
4. **데모**: 지역 선택 → 캘린더 → "이번 달은 평년 대비 +180%" → CSV 다운로드
5. **영향**: 조기경보, 자원 배치, 화재 시즌 계획 / 향후 VIIRS 전용 시대에도 연속성 보장
